1. `00-vision.md` — product goal, scope and compatibility stance.
2. `01-dsh-principles.md` — the DSH plugin/capability model.
3. `02-reference-analysis.md` — official DSH, dsh-agent-teams and JiuwenSwarm roles.
4. `03-capability-family.md` — target package and service graph.
5. `04-core-protocol.md` — revision, attempt fencing, mailbox, scheduling and recovery.
6. `05-jiuwen-feature-mapping.md` — mapping external concepts to DSH plugins.
7. `06-workspace-distributed.md` — Worktree, remote members and atomic state.
8. `07-implementation-roadmap.md` — staged delivery and exit criteria.
9. `08-testing-verification.md` — verification matrix.
10. `09-sources.md` — source pins and evidence policy.
11. `10-fusion-audit.md` — current reference fusion, conflicts, gaps and optimization priorities.
12. `11-official-first-development.md` — mandatory official-first compatibility and development gate.
13. `OFFICIAL_BASELINE.json` — machine-readable official remote/package/evidence baseline used by `pnpm verify:gate-a`.
14. `12-independent-review-management.md` — independent reviewer autonomy and project-manager boundaries.
15. `13-self-hosting-dogfood.md` — staged DSH RPC dogfood, stable/candidate Profiles and self-improvement control loop.
16. `reviews/` — immutable independent reports and separate project-manager intake records.
17. `adr/` — accepted architecture decisions.
18. `development/` — bounded implementation commissions and stage completion reports.
