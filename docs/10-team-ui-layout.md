# 10. Team UI 布局与交互设计

本文件定义 Team 界面的信息层级、布局和交互。总体架构见 [03-capability-family.md](03-capability-family.md)，身份、读权限、导航与状态合同见 [04-core-protocol.md](04-core-protocol.md)。第 8 节是用户确认的 V7 群聊开发设计；第 1–7 节保留个人会话工作台的适用规则。设计定稿不等于功能已实现，交付状态须由对应候选的真实浏览器与运行证据确认。

## 1. 用户要看清什么

进入页面后，用户应能直接识别当前在和谁对话、这个人属于哪个 Team、谁是队长、任务正在推进还是等待处理，以及在哪里打开个人对话。多 Team 共用一个工作界面；Main Brain 主会话保持自己的身份。

| 区域 | 主要问题 | 主要信息 |
|---|---|---|
| 官方会话栏 | 我打开的是哪个会话？ | 官方 Session 名称与列表 |
| 中央会话顶部 | 当前是谁、属于哪个团队？ | 主会话 → 短 Team 名与队长名 → 成员名、官方子会话计数 |
| 中央对话 | 当前这个 Agent 在做什么？ | 该 Session 的消息、工具结果和官方输入栏 |
| 右侧 Team 页签 | 全队进展如何？ | 多团队卡、进度、待办、Captain → Member → 当前任务 |
| 成员详情 | 这个人具备什么、正在做什么？ | 个人资料、当前任务、运行、Skills 与工具、成果与成长 |
| 官方插件设置 | 新建团队使用哪些默认配置？ | provider/model、Skills、工具策略、交流与资源配置的已支持项；推理等级由工具调用参数指定 |

## 3. 团队卡与执行树

同一主会话的关联 Team 纵向排列，每个团队一张卡。默认展开一个团队，其余保持摘要；进入队长或成员 Chat 时优先定位其真实所属 Team，用户显式选择的其他 Team 按当前 Session 保留。

```text
▼ 星河                 活跃             [打开队长对话]
  队长 北辰 · 成员 2 · 已完成 3 / 5
  进度：完成 3 · 执行 1 · 待审核 1
  待处理：1 项审核
  [公开目标 ▸] [最新公告 ▸]
  [任务] [成员] [群信息]

  北辰  队长
  ├─ 衡准  质量验证     验证中      [打开对话]
  │  ├─ 当前任务：检查交付结果
  │  └─ 成员详情（点击本人后原位展开）
  └─ 砺行  功能实现     执行中      [打开对话]
     └─ 当前任务：完成实现
```

卡片摘要来自同一个 Team projection。已完成数只统计 canonical completed；submitted 显示待审核。未知依赖显示“依赖状态待确认”；截断读取应提示已显示范围，不生成虚假的总体百分比。没有计划、空公告和技术诊断不占据默认概览；折叠目标和公告不折叠进度与待处理事项。

成员行按 Captain → Member 缩进，当前任务位于该成员下方。只关联当前 attempt；旧任务、旧身份、移除成员不能继续显示为当前工作。当前会话标记与正在查看的 Team 卡是两个信息：查看另一个 Team 不等于跳转到它的 Captain。

| 卡内视图 | 默认内容 | 操作结果 |
|---|---|---|
| 任务（默认） | 按真实状态分组的任务卡片、当前执行信息与更新时间；已完成分组默认收起，依赖图可展开 | 进入栏内任务概览或轨迹，返回恢复原任务卡焦点 |
| 成员 | Captain → Member 执行树与当前任务 | 展开成员、打开个人对话或任务详情 |
| 群信息 | 队长公告、已有团队管理请求与诊断入口 | 公告保留来源与时间；交流强度请求排入队长会话，权威读回后才标记已应用 |

任务概览通过独立 `taskDetail` 读取真实任务正文、完成标准和已保存的输出；状态、执行者、指定成员、依赖、创建与更新时间及当前 attempt 使用同一次详情响应，避免与较旧摘要混合。轨迹按当前保留的本任务 attempt 分轮显示输出、证据引用、诊断、分派记录时间和被替代的尝试。字段缺失显示未记录，详情请求失败、任务不存在和读取超限分别说明；来源角色、审核者及阶段事件当前不可读，不补造审核原因或时间。

打开可见任务详情时读取，随后只在已验证的 snapshot 稳定游标变化时刷新；概览/轨迹切换与内容未变的轮询不重复请求。返回列表、切到其他分区、关闭正文或切换 Session/Team 时取消该详情读取，并按调用 Session、解析后的 root、Team、任务、游标与修订隔离迟到响应。读取结果不形成新的持久化缓存或权限。

轨迹明确显示当前 retained 尝试的返回数、保留数和上限；截断与已被保留策略移除的历史分开说明，不能称为完整历史。证据按纯文本显示，不推断为存在或可访问的文件；诊断不自动等同于退回原因，分派送达记录时间不等同于模型开始、提交或审核时间。字段与读取边界见 [核心协议](04-core-protocol.md#8-持久化读取与-ui)。

任务详情、概览/轨迹选择、轮次与已完成分组的展开状态按 root Session + Team 保留；关闭并重新打开官方侧栏、切换 Team 后可恢复。该状态仅保存浏览偏好，任务事实仍来自 Host，刷新页面或重启浏览器后的偏好恢复不在此首片范围内。

## 4. 成员详情与任务详情

成员详情在本人分支内展开，不覆盖中央会话，也不创建第二个成员导航栏。成员身份与当前任务始终位于其三个详情页签之外。

```text
└─ 衡准  质量验证                             [打开对话]
   头像  姓名 / 职责 / 职业
   性格、简介、已知模型信息
   当前任务：检查交付结果 · 执行中 · 开始时间
   ┌─────────┬──────────────┬────────────┐
   │ 运行    │ Skills 与工具│ 成果与成长 │
   └─────────┴──────────────┴────────────┘
   所选页签的资料
```

运行页展示官方组合可读的 provider、model、preset 与状态；资料中保存的模型不能冒充最新请求已使用的模型。Skills 展示 Team allowed、成员 assigned、Session-visible 等各自已支持的投影；工具按实际可见/限制信息呈现。成果只显示有来源的输出与记录，不能从职业、头像或记忆推断成长。成员私有记忆保持私有。

任务、预算和诊断详情沿用栏内切换与明确返回入口；不使用 modal、absolute 详情遮罩或插件自有全屏回退。长资料单行省略并提供完整文字访问，普通正文在栏内换行，局部横向内容按需滚动。键盘用户可到达操作与返回入口，焦点不能掉回页面起点。

## 5. 会话顶部短名称

此项是当前改版需要接入的显示规则，依赖 Core 的通用 lineage display seam；正式安装与浏览器未验证前，不能把源码或测试截图作为已上线证明。

| 对象 | 可见文字规则 | 完整信息与回退 |
|---|---|---|
| Main Brain | 保持官方主会话名称 | 选中 Team 不改名 |
| Captain | `短 Team 名 · 队长自定名` | Team 名最多取 6 个 Unicode 码点，再加省略号；完整 Team/队长名保留在悬停文字 |
| Member | 成员自定显示名 | 无自定名时用真实 roster 名；悬停显示 Team、Captain → Member |
| 后代数量 | `xN` | N 取官方控件提供的后代计数，不用 Team roster 数替换；完整含义沿用官方可访问标签 |
| 关系不明或数据不可用 | Core 原始文字 | 非 active、错误父级、成员已移除、非 continuable、stale 或不完整读回不得显示猜测名称 |

同一规则应用于官方顶部 lineage 行和官方切换列表的对应文字槽。插件只提供文字，导航、选中、展开、计数来源与可访问性由官方控件拥有。身份随权威读回更新，不复制一份姓名缓存或启动第二个轮询器。

## 6. 窄屏、状态与输入区

窄屏由官方宿主决定右栏分栏或浮动；Team 内容始终适应实际容器宽度，不能依赖浏览器外窗宽度假定存在三列。卡片、树和详情在栏内纵向流动，长名称不会撑宽页面。

```text
官方宿主打开 Team 时：
┌────────────────────────────┐
│ 官方返回 / 关闭    Team     │
├────────────────────────────┤
│ 主会话 › 星河 › 衡准       │
│ ▼ 星河 · 北辰              │
│   进度与待处理事项         │
│   任务 / 成员 / 群信息      │
│   北辰                    │
│   └─ 衡准                 │
│      当前任务与成员详情   │
│ ▶ 远山 · 司南              │
└────────────────────────────┘
```

| 状态 | 页面表现 | 操作边界 |
|---|---|---|
| 首次读取 | 明确加载提示；没有完整 Team 关系时不显示伪空卡 | 不把上个 Session 正文挂到新目标下 |
| 无团队 | 保持官方会话体验 | 不强行打开空 Team |
| 断线 / 陈旧 | 概览与详情同时提示，已有内容有明确陈旧标记 | 未重新验证的地址与绑定不能当作当前事实 |
| 重连 | 读取当前目标并恢复可验证内容 | 不抢回用户关闭的侧栏或页签 |
| 导航失败 / 成员不可用 | 显示失败或不可用原因 | 不猜 URL，不向另一会话发送操作 |
| staged Team | 明示尚未创建 Captain | Captain Chat 入口不可用 |
| 已归档 | 明确历史阶段 | 不伪造 active 成员或当前工作 |

中央输入区复用官方 Composer。当前会话可停止时保留 Stop；发送能力不可用时不应并列显示一个会误导用户的 Send。该行为归 Core 会话 UI，须按实际在线、离线和运行状态独立验证；Team 管理消息的队列状态不能代替官方输入状态。

## 7. 验收场景与实现入口

验收用例见 [08-testing-verification.md](08-testing-verification.md)。下列结果必须在实际官方布局中观察，不能只靠组件 fixture：

1. 主会话下至少两个 Team：卡片纵向排列，切换只读目标时没有旧正文串入。
2. 进入成员 Chat：官方顶部显示正确队长/成员短名，侧栏标记其所属 Team；点击返回主会话，落到精确 root Session。
3. 第一遍打开、快速来回切换、侧栏关闭和其他页签选择：无错误 Session 页签、焦点抢占或重复监听。
4. 成员身份更新、移除与父级不匹配：正确更新或回退，官方数量不被 roster 数覆盖。
5. 成员详情、任务详情、长文本、窄栏、官方浮动布局、键盘操作与读屏名称：信息可读、操作可达。
6. 加载、断线、重连、归档及 staged Team：状态诚实，权限仍由 Host 验证。
7. Captain 显式路由和自身换模型：用真实请求与冷恢复证明路由，不能只验设置页文字。

## 8. 团队公共群聊：V7 定稿

本节定义“Team 主入口为公共群聊，每人保留独立执行 Chat”的已确认方案。唯一视觉基线为 [V7 交互原型](assets/team-group-chat-v7.html)，文件 SHA-256 为 `217AF363D740E31D107A408B119B691130F5D03D807E0207CCEFCC486B9C77FB`。原型内的人名、消息、任务、时间、执行轮次及产物都是设计样例，不得作为生产种子或真实证据。功能范围见 [产品设计](00-vision.md#31-团队公共群聊功能定稿)，消息权威、共享目录和自主视觉协助见 [架构设计](03-capability-family.md#61-公共群聊的候选架构)。第 1–7 节的个人会话工作台按现有合同运行；群聊资料卡与本节冲突时以本节为准。

### 8.1 定稿布局与导航

```text
┌──────────────┬─────────────────────────────┬──────────────────────┐
│ [导航收起]   │ 星河 · 群聊                 │ 任务 / 成员 / 群信息│
│ 星河 群聊    │ 团队目标摘要 / 推进状态 ▾  │                收起│
│   │ 北辰 队长├─────────────────────────────┤ 需处理：资料复核    │
│   │ 砺行     │ 用户：@砺行 请检查这张图   │ 进行中：窄屏布局    │
│   └ 衡准     │ [图片缩略图]                │ 待认领：任务用语    │
│ 远山 群聊    │ 砺行 → 衡准：请协助看图    │ 单击任务查看详情    │
│              │ 衡准：引用图片的检查结论    │                      │
│              ├─────────────────────────────┤                      │
│              │ 输入消息，@ 选择成员        │                      │
│              │ [图片缩略图 ×]              │                      │
│              │ [添加图片]          [发送]  │                      │
└──────────────┴─────────────────────────────┴──────────────────────┘
```

左侧保留直接可见的团队菜单，不替换为会话下拉框。“团队群聊”与官方“工作区”标题同级，沿用其字号、色阶、对齐和间距；团队区顶部不重复显示 Main 会话入口，Main 仍从官方工作区访问。单击团队群名同时选择该群并切换它的成员展开状态；当前群再次点击只折叠成员，不重置消息和草稿。移除群名前独立的展开/收起箭头。成员竖线和缩进列表嵌套在所属团队群聊项内部，点击成员只进入该成员个人 Chat，不触发父项折叠。顶部导航按钮只控制整个左栏，群头保留当前 Team 身份。左侧是个人 Chat 的单一入口，不显示“个人执行 Chat”分组标题；右侧资料卡和群消息不重复增加聊天按钮。具体接入官方布局的 seam 须以真实组合验证，不能覆盖 Main Brain 身份或用假 Session 表达群聊。

右栏默认显示任务，顶层只有“任务 / 成员 / 群信息”三个页签。右栏打开时，唯一“收起”按钮在栏内；关闭后群头才显示“展开团队栏”，不能在群头复制三个页签。折叠、切页签和宽度变化保留所选任务、概览/执行轨迹、历史轮次展开、产物预览及草稿状态；重新展开回到原位置。Task 详情仍位于同一栏，不再叠加另一列。

同一 Team 内切换队长或成员个人 Chat，只更新中央会话及当前成员标记，保持右栏已选页签、任务和展开状态；不得自动跳到成员详情，也不得清空后重载成员网格与群聊历史。新 Session 的关系核验期间可保留同一已验证 Team 的只读画面，新的读写请求须等新目标关系验证后恢复；跨 Team、关系失效与迟到响应继续隔离，不能用保留画面绕过 Host 验证。

右侧“成员”采用紧凑头像网格，头像放在明确的 44–48px 容器中，每项只显示姓名和简短身份；姓名截断时提供完整可访问名称。单击打开独立浮出资料层，不在网格或菜单下方追加长卡；同头像再次点击关闭，点击另一头像切换成员。桌面通过 portal 脱离宿主滚动裁切，靠近触发头像定位，空间不足时翻转并限制在视窗内；窄屏使用独立底部资料层。左侧个人 Chat 入口保持不变。

成员资料固定头部只显示 48px 头像、姓名、角色、真实状态及最多两行职责，下面紧接“属性 / 工作 / 能力 / 成果”四个短页签。关闭、姓名和页签始终可达，只有当前分区正文独立滚动，切分区滚动归顶。各区内容如下：

| 分区 | 内容与边界 |
|---|---|
| 属性 | 职业、性格、简介；职业与本队职责分开，未知值明示。字段来源和更新时间就近简写，完整来源、版本、Session ID 与诊断默认折叠 |
| 工作 | 真实当前任务的标题、状态和短编号；点击打开右栏已有任务详情并关闭资料层，不新增一列，也不跳转个人 Chat |
| 能力 | 当前模型与图片支持状态；Skills 的分配、当前可见和目录分别成段；工具可见性和团队权限单独成段。长技能与工具列表可折叠，不能把分配当作实际可用 |
| 成果 | 有来源的最近结果和保留范围内统计，明确记录范围与缺失，不把有限保留记录当作完整成长历史 |

打开资料聚焦标题；Esc 或关闭按钮恢复原头像焦点，外部可操作控件点击关闭资料但保留该控件的操作和焦点。桌面 Tab 离开资料层时自然关闭，窄屏 modal 在层内圈定焦点。切 Team、成员移除、触发头像卸载或滚出可见区域时关闭；滚动、缩放和分区尺寸变化重新定位，不重置成员。资料层不能清空草稿、推动网格布局、带动聊天滚动或遮住自己的关闭入口。

### 8.2 输入、提及与消息草稿

输入栏不设“交给”下拉框。默认空草稿只提示“输入消息，@ 选择成员”；在没有有效提及时以低强调文字说明“默认由队长处理”。`@` 表示公开消息的处理对象，不是私聊。

| 操作 | 交互规则 |
|---|---|
| 键入 `@` | 在输入区附近打开本队成员候选，按输入检索；中文或标点后直接输入也触发，如 `请@衡准`，不要求前置空格。每项显示头像、名字、职责及图像能力，同名成员要能区分 |
| 选择成员 | 插入绑定稳定成员 ID 的 mention token；消息显示姓名，改名不改变接收身份。已移除/不可用成员不能悄悄替换成别人 |
| 键盘与输入法 | 上下键选择候选，Enter 确认，Esc 关闭；中文输入法组合期间不触发发送。普通 Enter 换行，Ctrl/Cmd+Enter 发送 |
| 多个提及 | 允许多个已确认 token，按稳定 ID 去重后分别定向投递；不提供隐含全员广播。普通文字中仅出现名字不算提及 |
| 手输或粘贴 `@名字` | 尚未确认的提及须提示选择成员，不能猜测同名身份后发送，也不能静默改成默认队长；候选检测与未确认提及检查使用相同起点规则 |
| 编辑 token | 整体删除或重新选择；普通复制来的文本不继承接收权限 |
| 切群或个人 Chat | 按真实群/会话身份保留各自草稿、提及与附件，返回恢复；切换不能把上一群内容发给新目标 |
| 发送过程 | 提交期间防止重复点击；失败保留草稿并可重试。成功清空当前草稿，公共消息显示真实投递状态 |

`@` 候选不覆盖发送按钮或裁出视窗，候选很多时使用有限高度列表；键盘焦点与读屏活动项对应同一个候选。点击成员资料、切发言模式说明或查看任务不应清空输入草稿。

### 8.3 图片附件与自主视觉协助

图片按钮与发送按钮放在输入框底部两侧；支持本地选择、粘贴和拖放。附件缩略图位于编辑区内，可查看文件名和移除。首期只显示图片入口，不把视频列为可用操作。原型的本地图片预览必须标明本地状态，不能声称已上传到 Host。

| 状态 | 用户可见行为 |
|---|---|
| 草稿图片就绪 | 显示缩略图，可移除；允许只发送图片 |
| 读取/上传中 | 显示进行状态，整条消息暂不可提交 |
| 格式/大小/像素不符或上传失败 | 保留草稿，说明原因，可移除或重试；实际限制取自 Host，不在设计中猜固定值 |
| 接收人不支持看图 | 保留用户选择；提示其可请视觉队员协助，不强制用户改接收人，也不自动替换模型 |
| 群内发起协助 | 显示“砺行请衡准看图”，关联原消息和图片；协助摘要回报有来源，原负责人保持不变 |
| 无可用视觉成员 / 能力未知 | 显示“等待视觉协助”或明确能力待确认，原接收人或 Captain 处理；不伪造识图结果 |

群中能查看原图片和相关回答，详尽工具轨迹保留在个人 Chat。图片公开范围与原消息一致；“已上传”“已排队”“视觉成员已处理”不得混成一个成功标记。共享目录由模型可读来源更新，资料卡显示并不证明成员已读取最新信息。

### 8.4 发言模式：扩展记录，不实现运行

发言模式在“群信息”的折叠说明中展示，群头不放模式菜单。保留简短解释：“队长协调：队长统筹、定向协作”“轮流发言：按轮次依次回应”“自由发言：成员按规则主动参与”。后两项显示“扩展预留”，本轮不执行调度或保存生效；原型可查看规划说明，不演示虚假的轮次与全员自动回复。

公开可见范围由群聊本身表达，不随发言模式改变；现有交流强度也不自动映射到这些模式。以后切换时应显示当前模式、待应用状态及失败原因，并允许用户明确停止/暂停发言调度。轮流与自由模式的权限、并发、预算、终止及冷恢复设计由架构和产品文档记录。

### 8.5 窄屏、异常与验收

窄屏把成员、任务、群信息入口保留在群头附近，通过同一侧栏/抽屉或栏内面板展示，不要求用户滚到整段群聊底部才能查看资料。团队栏有高度边界且正文独立滚动，不能在聊天前无限延伸。中央消息区独立滚动，输入和发送保持可达。目标摘要默认收起；任务进度和待处理信息只在任务页，目标详情与公告不作为所有右栏页签的共同前缀。资料、模式和 `@` 候选互相避让；关闭或返回恢复原入口焦点与未发送内容。至少检查 390px、768px、桌面宽度及宿主侧栏收窄后的实际容器。

| 情境 | 验收要求 |
|---|---|
| 草稿与提及 | 无 @、多 @、同名、改名、退出、中文输入法、Enter/Ctrl+Enter、切 Team 后草稿不串入 |
| 附件 | 仅图片、文本加图、多图、格式错误、失败重试、移除和发送中切换；没有视频发送入口 |
| 人员导航 | 左侧成员打开个人 Chat，右侧头像只展示完整资料；折叠不丢当前会话；无重复 Chat 操作 |
| 视觉协助 | 原接收人自主选择视觉队员，引用原图回报、无递归转交或责任暗改；能力未知和无视觉成员有明确结果 |
| 共享目录 | 名字、性格、简介、Skills 和真实能力改变后，UI 与队员读取一致；资料未完整时明示 |
| 模式扩展 | 能查看规划内容，但不误标轮流/自由模式已经生效 |
| 可达性与恢复 | `@` 列表、资料卡、图片操作不裁切，键盘与触摸可达；重连与重启后不重复消息或派工 |

**已批准的群聊阅读交互。** 中央 `.swarm-public__messages` 保持唯一主滚动区，固定群头与输入区沿用现有结构。任务活动以序号、时间、事件、实际参与人及任务链接组成紧凑时间线，可收起并保留最后一条已载入活动摘要；原始提案和保留范围仍可展开检查。顶部只有一个定位菜单，提供“任务活动 · 群聊顶部”和“已载入消息末尾”。后者只定位已经读回的末条，不承诺服务器最新；现有前后分页按钮和权限判断保持有效。

连续正文按实际排版测量，超过约六行才出现“展开全文 / 收起正文”；短文不增加按钮。图片保持原次序并独立展示，不计入文字折叠高度。引用默认单行省略，悬停、键盘聚焦或触摸可查看完整文字，Tab 可进入原文链接、关闭与全文滚动区，Escape 返回触发按钮；自有浮层使用 body portal 避免群消息/输入区裁切。定位原文仅在原消息已载入时可用。当前组件生命周期内，按调用 Session、Captain 与 Team 的选择键保存阅读锚点、活动及正文折叠偏好；展开、收起、前后分页、推入新消息、切群返回及同一消息内图片迟到不自动追尾。草稿和消息事实继续由原 controller 管理。

**统计范围与官方复用边界。** 群聊使用官方全局 `useSessions` 读取当前调用会话的公开 `SessionSummary.projectionValues`，只在 Team 已验证、官方列表 ready、`current === selection.viewer` 时显示已知数据，并标注“当前会话 · 标题”。总量来自 `tokenUsage` 的 `uncachedInputTokens + cacheReadTokens + cacheWriteTokens + outputTokens` 四个不交叠桶；平均输出速度沿用官方 `sessionStats.decodeTokens / (decodeMs / 1000)`，轮数/步数及模型/工具耗时读取同一官方投影。缺值、非有限数、负值、零解码时间、切换和陈旧状态显示 `—`，不能把团队总量或当前会话用量写为单条群消息用量，也不从消息字数/到达时间估算速度。

目标 alpha.2 的 `StatsPills` 属于官方聊天内部组件，未提供公开导出；其 composer dock 受 slot children 所有权限制，不能在自定义 main 下直接重用或重新声明。当前仅复用公开 Session 投影、标准 hook 与官方 Modal，保留相近的两个统计入口和明细布局；不拷贝私有组件、不增加 RPC/轮询或 Session 状态 owner。官方以后提供可组合组件时再按功能完整性优先原则评估。以上是组件合同，真实安装与功能验收仍需候选对应的 Profile/浏览器证据。

完整功能验收链路为：用户 `@` 非视觉成员并附图 → 该成员读取同队共享目录 → 自主请求视觉成员协助 → 群内可追溯回报 → 原成员提交 → Captain 审核 → 打开个人 Chat 核对执行 → 重启后继续读回。开发按第 8.7 节分段闭合，不把原型样例作为这条链路的实际验收。

### 8.6 团队目标与任务面板的选定方案

沿用三栏群聊，将群头置顶公告占位改为 **团队目标** 摘要条，右侧默认打开 **任务**，仍保留 **成员 / 群信息**。目标、任务、聊天分别承担结果、行动与讨论，保持同时可见。未选中央“目标 / 任务 / 聊天”三个大页面：该布局虽能放宽看板，但频繁切换会割裂讨论与任务，本轮无需另建工作台。公告只作为有时间和来源的通知保留在群消息/群信息，不占第四个页签。

**目标摘要与展开。** 默认显示一行目标、推进状态和展开入口；窄屏摘要最多两行，展开后仍能查看全文。展开区显示期望结果、完成标准、约束、工作方式与当前下一步/等待原因；放置一项主要的开始、暂停新增工作或继续动作，以及调整目标入口。持续维护的触发、周期与预算收在展开区，不在群头叠加另一组模式选择器。发言模式说明留在群信息，分配方式只出现在具体任务详情。

目标调整的保存结果与任务调整分开显示。已保存但 Captain 尚未协调时明示“目标已更新，等待队长调整任务”；现有任务保持原来的来源与结果。正式表单通过已认证 `goal/v1` 保存完整结果、完成标准、约束和工作方式，提供“保存”及明确的“保存并开始/继续”。维护填写 60 秒至 7 天的完成后间隔，并显示“团队 Token 总上限（含已使用）”；原用量和其他限额保留，有限上限与开始条件由 Host 同一事务校验。能力未知或不支持须明确显示，不借当前 Chat 成员身份操作；workflow-only 的自主开始不可用仍不妨碍保存或暂停。

草稿和待确认操作独立于聊天，按 Host/Main/Team 持久保存。发送前落盘同一 requestId、原 lifecycle revision、完整载荷与预算旧上限；未知响应只能查询或重试原操作，超过 256 份回执恢复窗口显示“原操作结果无法确认”，不得自动换 revision 重发。迟到回包不清除其他 Team 或继续编辑的草稿，也不能覆盖已经读到的较新协调状态；刷新、重连沿用原 dashboard owner。

推进状态与工作方式分开：持续维护不是“已完成”之类的阶段；维护轮次结束显示待命及下一触发条件。任务完成数量是任务统计，不能写成目标完成度。暂停文案固定为“暂停新增工作”，同时提示已分配/执行中的工作仍会收尾；不得让用户误以为所有运行都立即停止。

**任务列表与详情。** 右栏按需处理、进行中、待安排与等待、已完成分组；已完成默认折叠。每张整行可点击卡片显示标题、真实状态、负责人、短任务编号、当前动作及事实时间；标题可换行，未知时间不编造。栏首只保留任务数、未完成数与“提出任务”，不增加统计看板、筛选器或横向任务列。只有明确 open-claim 且已可执行的任务才显示“待认领”；automatic 未分配显示“待安排”，前置未满足显示“等待依赖”。暂停期间保留任务事实，并说明新增认领不可用。

点击任务进入同栏详情，固定顶部包含返回、编号、状态、标题、执行者和验收者，二级页签仅为“概览 / 执行轨迹”。概览先呈现当前动作与等待原因，再呈现说明、完成标准、实际提交结果和可点击依赖；来源与分配方式收在次级信息中。返回恢复任务行焦点及列表位置。来源区分原始提出人、实际创建者、执行者与验收者；投影缺失字段显示“当前接口未提供”，只有权威确认没有保存才显示“未记录”，不能由 Captain 身份或最近消息推断。用户视角不显示冒充成员的“我认领”，开放任务可提供“请队长安排”；成功分配前仍保留待认领状态。成员的自主认领由其官方 Session 调用任务能力完成，群中显示实际认领结果。

**执行轨迹。** 使用已有任务与 attempt 权威按真实时间排列创建、分配/认领、执行、提交结果、审核和退回。每轮显示实际执行者、起止事实和状态，当前轮默认展开，旧轮默认折叠；首次打开后保留用户选择。退回原因与对应提交/审核位于同一轮，返修形成新轮并保留旧结果；“已提交待审核”不能画为通过或完成。协助记录引用原消息、实际协助人及结果，标明协助不改变 owner。未接入协助/创建来源时显示“当前接口未提供”，只有权威确认无记录才使用空记录文案；没有 attempt 的任务不生成空执行轮。被保留策略裁剪的历史明确标记范围，不能声称已展示完整历史。过渡切片只能把现有 attempt 的创建时间与最后更新时间按原意展示，不能由 updatedAt 补造提交/审核时间。

产物只展示实际已提交且可访问的引用；点击通过受支持的产物查看/文件能力打开，失败显示原因。权威明确没有提交时显示“尚未提交结果”；投影未提供产物字段时显示“当前接口未提供结果详情”，不能把不可见等同于不存在，也不能把示例 Markdown、任意路径或模拟下载当作真实产物。

**提出任务。** 人类默认入口叫“提出任务”，位于任务面板标题旁；表单只要求希望团队做什么，完成标准可选。提交后显示“已交给队长整理”，正式创建成功后才产生任务卡和引用；未创建的请求不计入任务总数或完成进度。主智能体提交也保留真实来源。已有授权范围内的成员可直接创建和认领，不强制经过同一人类表单或额外审批；范围不清时才主动提议。执行成果统一叫“提交结果”，避免与工作请求混淆。

表单草稿与聊天草稿独立，暂存、切换资料或返回任务不能清空聊天；未提交内容按所属 Team 恢复。人类请求、目标调整、群聊发送分别展示处理状态，不能把一个“提交成功”扩大为任务已经开始、目标已被消费或结果已通过。

**宽度与样式。** V7 桌面基线为左导航 166px、中央聊天自适应、右栏约 320px（宿主允许时在 300–360px 内调整）。使用现有 DSH 字体、主题色、浅边框和轻分隔线，详情正文至少 13px；状态不能只靠颜色。按可用内容宽度统一布局判断，原型在 840px 及以下把同一右栏放在群头下方、消息上方，500px 及以下左导航放在顶部且可整体收起；初始保留 V7 可见导航，不暗改为下拉菜单或默认隐藏。不能让 CSS 视口断点与 JS 容器判断不一致而留下空列。至少核验 390px、768px、断点附近和 1024px，缩放后所有入口可达且无横向溢出。头像网格、资料卡、左侧个人 Chat 单一入口、`@` 和图片草稿继续遵守前述约定。

新增设计检查覆盖：群名单击收展且成员仍嵌套、右栏只有一组页签和条件显示的收展入口、任务详情与轨迹状态保留、目标展开/调整后任务保持原状态、暂停与收尾文案、待认领与待安排/依赖的区分、提出任务不冒充正式创建、不替成员认领、返回焦点、表单与聊天草稿隔离。真实开放认领、目标协调与维护机制的验收范围以 [架构 6.5 节](03-capability-family.md#65-目标推进与任务认领的候选扩展) 为准。

### 8.7 开发切片与完成边界

以下定义交付顺序和验收，不充当实时任务看板。每个切片在现有任务协调器中保留 owner、基线、RED/GREEN、冻结候选与未完成项；GitHub PR 保存审查与集成结果。

| 切片 | 可观察结果 | 必需证据 |
|---|---|---|
| 任务阅读 | 真实任务列表进入概览/分轮轨迹；列表返回、关闭恢复与窄栏可用 | 当前 Host 合同的组件回归、真实官方 Profile 与浏览器；缺失历史诚实显示 |
| 公共文本链路 | 左侧进入真实群聊；人类消息经 Host 校验耐久提交，默认交 Captain，公开回报引用原消息 | 身份/跨 Team 拒绝、幂等、投递与消费分离、官方 Session 输入、冷恢复 |
| 提及与共享目录 | 稳定成员 ID 的多 @ 和同队完整资料同时供 UI 与 Agent 使用 | 中文输入法/改名/退出/同名、草稿隔离、权限与目录 revision 更新 |
| 图片与视觉协助 | 图片真实进入指定成员，非视觉成员自主请视觉队员协助，原 owner 提交并经审核 | 官方附件 admission、真实模型与原图、协助去重、失败/撤权、重启恢复 |
| 工作请求与任务关联 | 人类提出的工作由 Captain 整理并创建正式任务，群内可追溯回报 | 人类身份、原请求幂等、来源与执行/验收分离，失败不冒充派工 |
| 开放认领 | 符合资格的成员收到通知并原子自领，可由 Captain 改指派 | 通知恢复、竞争、依赖、busy、预算、revision 与 attempt fencing |
| 目标推进 | 修改目标与协调结果分开读回；暂停全部新 attempt 入口，已分配工作收尾；维护可待命恢复 | 单一编排 owner、各入口一致性、真实运行/停止/冷恢复 |

各切片先完成最小可证伪检查，再实现、受影响回归、冻结候选工程门、独立审查和串行 GitHub 集成。新功能不能破坏已有 Main/Captain/Member 个人 Chat、模型路由和官方 Stop。预览、工程通过、真实运行、冷恢复与生产部署分别报告；没有该能力的阶段不显示可生效的按钮。轮流/自由发言、视频、远程执行和其他已有仓库事项不并入本轮群聊范围。
