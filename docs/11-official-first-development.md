# Official-first 开发

插件只通过官方 DSH 的公开扩展面工作。官方 DSH 服务和 Session log 始终是运行与会话权威。

## 固定基线

- 官方源码基线由 `docs/OFFICIAL_BASELINE.json` 固定。
- 当前审计基线包含官方 DSH commit `b2e3b2a0125854567a4a5fcba75782e42fe84901`（`0.1.5-alpha.2`）。
- 实际 API 以本仓库安装的 `@deepseek-ai/*` 包、类型声明和公开测试为准。
- `ref/` 只读，只能通过仓库提供的同步脚本刷新。

## 允许的扩展面

- Plugin 注入和 disposer；
- Provider、Consumer、tool、event；
- storage form 与 Bundle composition；
- 官方公开客户端组件、设置扩展和主机上下文。

禁止私有路径导入、猴子补丁、复制官方状态机或直接改 Agent Loop。

## 修改流程

1. 在已安装包和公开类型中确认 seam，而不是凭记忆猜接口。
2. `src/domain/` 保持框架无关；Runtime 与 Host 在各自职责中消费官方公开 seam，客户端只消费浏览器安全合同和官方 UI 能力。
3. 为注册动作提供明确生命周期所有者和 disposer。
4. 权威提交后再发布投影；模型可见状态必须能由 Session log 和插件存储重建。
5. 官方基线、包版本或 seam 变化时运行 `pnpm verify:compatibility`。
6. 参考项目重新固定版本时，在手动 Gate C 运行 `pnpm verify:anchors`，逐项处理缺失文件、越界行号和上下文标识符不匹配诊断。该检查覆盖两个参考仓库的简单 `path:line` 引用；当前文档未使用此类引用时，零命中只表示没有可检查的行号锚点，不代表完整的语义验证。

## 官方 Agent Teams 变更复用评估

以插件功能完整性为首要条件持续核对官方 Agent Teams。检查运行时、tool、client UI、Profile 组合及其公开类型、测试和发布物；同时识别被改名/移动的文件，以及由直接依赖 API 变化引起的实际行为差异。不得只看版本号或整个 DSH 仓库的提交数量。

1. 记录上次已检查的官方 commit、相关路径及发布包版本/完整性信息，区分源码观察水位、完整分析水位和当前安装基线。检查失败或分析未完成时，不推进对应水位。记录放在已有开发跟踪或自动化状态，不把提交的 Markdown 变成滚动状态库。
2. 检测官方更新后，读取自上次水位起的完整相关提交与净差异，检查发布物是否包含源码变化；文档、注释、测试与行为/API 变动分别归类。版本号变化不自动触发安装或依赖升级。
3. 将每个有行为意义的变化对应到插件现有源码、功能合同和测试，判断是可复用、兼容性影响、继续等待官方完善，还是无需处理。已经复用的官方底座与新的替换机会分开。
4. 复用会损害功能、权限、身份、事务、数据、恢复或流程时，放弃该项复用，保留现有实现；在已有 Issue 中写明受损能力、两边版本与依据、缺失公开接口和重新评估条件。官方没有解决该条件时不反复开工、不开发补丁或私有分叉，不阻塞其他已授权开发。
5. 官方补齐条件后才进入 [统一方案的采用流程](07-implementation-roadmap.md#21-官方-agent-teams-完整功能采用方案)，实际组合验证仍不可省略。兼容性修复与功能复用分开判断；不复用某个组件不意味着可以忽略已经使用的官方底座发生的破坏性变化。
6. 无相关变化时保持安静；有相关变化时提供简短的差异分类和采用结论，不将上游整仓无关提交当作通知。只在证据改变等待条件、出现兼容性问题或存在可验证复用机会时扩大调查。检测与评估不授权安装、生产切换或改动其他开发者正在写入的文件。

## 包与客户端边界

根导出提供插件配置、注入和服务 API；`./client` 只提供浏览器安全的 UI 入口。客户端不得导入 Node、文件系统、进程或服务端密钥能力。

## 兼容性结论

类型检查、模拟测试或静态源码审计只能证明对应层级。只有冻结包在全新官方 Profile 中加载并完成真实浏览器交互，才可声称该路径与当前官方基线兼容。
